# AI Analysis Templates Based on Context Packages

## Global guardrails

Use only attached context packages and approved Project Knowledge. Before answering, inspect `data_quality.validation_status`, `missing_sections`, `warnings`, `not_fully_confirmed` and `provenance`. Never invent missing values, suppress conflicts, treat current snapshots as historical data, or provide guaranteed buy/sell recommendations.

## 1. Single-ticker analysis template

### Purpose

Produce a structured, evidence-based description of one ticker using a validated context package.

### Required input

One `{TICKER}_context.json`, AnalysisGuide, AIUsageRules, and a user-specified purpose/cutoff. `corporate_intelligence` is optional for backward-compatible older context packages.

### Prompt

```text
Analyze the attached ticker context package for {TICKER}.

First report package generated_at/latest dates, validation status, missing sections, warnings, not-fully-confirmed items, and whether the request is current, retrospective or backtest.

Then describe only supported sections: identity/current metadata; price and liquidity with recorded calculation method and explicit price/volume basis metadata (raw/adjusted/unknown); financial summary with unit/availability warnings; valuation inputs without unsupported calculations; technical snapshot without certain predictions; shareholder snapshot with no-history warning; and news only if safely mapped.

If `corporate_intelligence` is present, report its top-level status and separately report `company_profile`, `company_subsidiaries`, `ownership_structure`, `major_shareholders`, and `corporate_events`. Preserve each provider/source scope, source identity, provenance, raw relationship semantics, and snapshot date exactly as supplied. Do not merge KBS and VCI records, equate fields with different provider semantics, or derive a common ownership/relationship taxonomy. Corporate Events are forward observations with incomplete coverage, not complete history, lifecycle status, cancellation, completion, or future actionability; do not use them alone for an investment recommendation. For major-shareholder deltas, use a change only when its own status says it is comparable; retain `incomparable` and its reason as a data warning.

If `historical_fundamental_brief` is present, consume it only from this final context package and label it **Historical FY2024 Fundamental Brief**. Preserve its `facts`, `data_warnings`, `supported_inferences`, `hypotheses`, `missing_evidence`, and `invalidation_conditions` as six separate sections, with its period, publication timestamp, consolidated scope, currency, scale, `historical_only` state, and `provenance_references`. Do not recompute any metric, merge facts with supported inferences, invent management explanations/catalysts/forecasts, or turn warnings and missing evidence into signals. Keep `hypotheses` empty when the brief supplies an empty list. If the brief is missing, malformed, missing a category, or missing historical metadata, report it as unavailable and omit it rather than reconstructing it. Always retain warnings for unknown price basis, unknown volume basis, unqualified current shares, and unavailable current-market trust. Any additional interpretation is unsupported and must be omitted from the final output.

Place verified Price Basis and Volume Basis metadata (`raw` or `adjusted` with `price_basis_verified=true`) under Fact; place `unknown` price basis, unverified adjustment claims, missing basis metadata, and `volume_basis_verified=false` under Data Warnings/Unknown; put any carefully qualified interpretation under Inference. Do not mix raw and adjusted series or assume volume is adjusted when price is adjusted. Place source-recorded Corporate Intelligence values under Fact; place `missing`, `partial`, `malformed`, `incomparable`, absent provenance, and snapshot-date limitations under Data Warnings/Unknown; put any carefully qualified interpretation under Inference. Missing or malformed Corporate Intelligence is a data limitation, not negative evidence about the company. If an older context package has no `corporate_intelligence` section, state that it is unavailable and continue only with the other supported context sections.

Separate Fact, Derived, Inference and Unknown. Cite internal provenance near important values. End with data risks, alternative interpretations and information needed for higher confidence. Do not issue ranking, buy/sell/hold language, a recommendation, target price, valuation conclusion, market-cap or enterprise-value conclusion, adjusted-return claim, portfolio sizing, backtest claim, or current-market momentum/technical claim.

If `current_state_price_analytics` is present, treat numeric values as Fact only when directly present in canonical context. Respect its `analysis_time_semantics`, `pit_backtest_eligible=false`, and `is_actionable=false`. `is_actionable=false` means the analytics lane cannot independently justify an investment action, but the AI should discuss and synthesize its recorded facts; `pit_backtest_eligible=false` means current-state analytics cannot be cited as point-in-time historical backtest evidence, but the current-state observations themselves remain valid descriptive facts. Bounded-window returns (e.g. cumulative return) and volatility/drawdown metrics are descriptive over the qualified observation window only and do not establish a long-term trend or investment signal. RSI is descriptive over its period (e.g. RSI14) and does not independently imply a BUY/SELL or timing signal. If `sma_20.status = unavailable`, the model MUST NOT fabricate SMA20, infer its value, replace it with current price, or state whether price is above or below SMA20.

If `current_state_market_risk` is present, treat beta and correlation as descriptive current-state statistics over the qualified benchmark observation window only. Preserve `paired_return_count` and `sample_adequacy`. `MATHEMATICALLY_COMPUTABLE` means the statistic could be calculated, NOT that it is statistically robust or significant. Do not claim statistical significance unless separately provided. Correlation does not imply causation. Respect `pit_backtest_eligible=false` (cannot be cited as historical backtest proof) and `is_actionable=false` (cannot independently justify an investment action). Describe market risk statistics as bounded by their reported `paired_return_count` sample size.

If `current_state_relative_valuation` is present, treat each method (`market_cap`, `pe`, `pb`, `ps`, `enterprise_value`, `ev_sales`, `ev_ebitda`) as Fact only when its own `state = "available"`; every other state (`unavailable`, `incomparable`, `malformed`) is a data limitation, never a value of zero or an implied qualitative judgment. Every available method mixes a current DNSE market price with an older, separately-dated qualified financial period — always report its `as_of_semantics` (`current_market_price_on_qualified_historical_fundamentals`) and never call it "TTM", "forward", or "current earnings"; state the `price_as_of_session`, `share_effective_date`, and the denominator's `financial_period` together, never just the multiple alone. `is_actionable=false` always. Treat `historical_comparison` as the sole authority for whether a current multiple may be compared against `relative_valuation`'s historical checkpoint: only `status="comparable"` entries under `comparisons` may be described as a change, quoting `multiple_change_pct` as a plain descriptive delta; an `"incomparable"` entry (including when it is incomparable only because the historical checkpoint itself is currently blocked) must be reported as a limitation, never silently treated as "no change" or skipped. Do not mix a `current_state_relative_valuation` figure with a `relative_valuation` figure outside of `historical_comparison`'s own verdict, and do not average, blend, or otherwise combine values from two different `financial_period`s.

If `foreign_flow` is present, treat it as a qualified foreign net transaction VALUE lane only over retained sessions. Do not infer qualified foreign volume, foreign room semantics, flow-to-turnover ratios, institutional accumulation, or causal price impact from foreign net buying/selling. Permitted phrasing may describe net foreign buy/sell value, direction, and session count over the qualified window, but must distinguish recorded observation from causal inference.

If `market_wide_current_liquidity_research` is present, treat it as a current-session (never historical, never point-in-time) DNSE board-composition reading only, valid for the ticker's own retained `session` date. Report `disposition` explicitly: `CURRENT_SESSION_DESCRIPTIVE_ELIGIBLE` carries a real reading; `INCOMPLETE`, `MISSING`, and `PROVIDER_REJECTED` are distinct data-limitation states, never a value of zero and never interchangeable with each other or with "no liquidity." An absent key means this ticker's session was never attempted at all — do not describe it using any of the four dispositions above. Treat `board_composition`'s four categories (`MATCHED_ROUND_LOT`/`MATCHED_ODD_LOT`/`PUT_THROUGH_ROUND_LOT`/`PUT_THROUGH_ODD_LOT`, i.e. DNSE boards G1/G4/T1+T3/T4+T6) and their `provider_raw_composition_ratio` as descriptive current-session composition only, never a liquidity, turnover, or executable-share ratio (`ratio_basis` says so explicitly). Report `g1_v_reconciliation.verdict` exactly as given: `EXACT_MATCH` and any other verdict (e.g. `OTHER`) are both legitimate outcomes to state plainly, never silently corrected, rounded, or described as an error to be fixed — a non-`EXACT_MATCH` verdict is itself a warning worth surfacing, not something to omit. `value_status` marks `grossTradeAmount` as retained-but-non-authoritative with an unresolved scale basis: never compute or imply a traded value, turnover, ADTV, ADV, position size, or execution capacity from it or from any other field in this section. `liquidity_research_contract` enumerates per-use authority states (`CURRENT_SESSION_LIQUIDITY_RESEARCH` may be `ELIGIBLE`; every historical/ADV/ADTV/sizing/execution/PIT use stays `BLOCKED`/`UNKNOWN`) — never treat a use this matrix blocks as available just because a different use is eligible. `is_actionable=false` always.

If `market_wide_current_descriptive_research` is present, treat it as a current-session (never historical, never point-in-time), market-wide descriptive breadth/sector/liquidity lane, valid only for the ticker's own retained `session` date. Always report `market_coverage` alongside any market-wide claim: `current_active_equity_denominator` is the full current-descriptive population, `observed_session_cohort` is how many of those actually have a same-session price bar, and `same_session_technical_feature_available_count`/`coverage_ratio_of_denominator` is how many actually produced a usable technical-feature reading — never describe a statistic bounded by the smaller same-session count as if it covered the full denominator, and never omit the coverage numbers when citing a breadth or sector statistic. `technical_features.is_current_session` distinguishes a genuine same-session reading from a stale prior-session value (`is_current_session=false`); a stale value may be reported only as "as of `feature_as_of_session`," never as today's return, momentum, or trend. `sector_classification`/`sector_state` are provider-descriptive industry or entity-class context, not a peer ranking; a `sector_state.status = "UNAVAILABLE_INSUFFICIENT_COVERAGE"` sector has too few same-session members to report any statistic and must be described as unavailable, never filled in, estimated, or treated as zero/neutral. `activity_and_session_state` values (`ACTIVE_LISTED_OBSERVED`, `ACTIVE_LISTED_NO_QUALIFIED_SESSION_OBSERVATION`, `INACTIVE_OR_DELISTED`, `UNSUPPORTED_OR_INVALID_PROVIDER_SYMBOL`, `UNKNOWN`) stay distinct from each other and are never collapsed into a simple "active" vs. "inactive" split. `liquidity` here follows the identical `market_wide_current_liquidity_research` semantics already described above (board composition, `g1_v_reconciliation.verdict` reported exactly as given including non-`EXACT_MATCH` residuals, `grossTradeAmount` non-authoritative) when `liquidity.status="ELIGIBLE"`, and is an explicit unavailable/not-applicable boundary otherwise. `blocked_outputs` enumerates every derivation this lane strictly prohibits (rankings, recommendations, probabilities/target prices, portfolio weights/position sizes, historical RAW_AS_TRADED/PIT, corporate-action/ex-date, backtesting, active-universe promotion, traded-value/turnover/ADV/ADTV) — treat every listed key as binding regardless of how favorable the underlying descriptive numbers look. `is_actionable=false` always.

If `market_wide_historical_research_context` is present, it is strictly `RETROSPECTIVE_DESCRIPTIVE_WITHIN_TICKER`: use its own `session`/`as_of_session`, `context_status`, retained-observation counts, range, drawdown, volatility, momentum, MA persistence, provider-scoped relative volume, technical-state frequency, structural state, blockers, and lineage only to answer where the ticker sits relative to its own retained recent history. `ADJUSTED_RETROSPECTIVE`, `raw_as_traded="NOT_PROMOTED"`, and `historical_pit_eligible=false` are binding: do not describe this as RAW_AS_TRADED, PIT, a historical return study, win probability, alpha, or executable backtest. `structural_state` is explicitly not an entry action or strategy-eligibility state; it must not alter research priority, entry action, sizing, or recommendation. Keep an `INSUFFICIENT_HISTORY`, `MISSING`, `PARTIAL`, or `NOT_APPLICABLE` context and each field-level reason exact; never fill a range, indicator, or volume value. A valid historical context and a valid `market_wide_current_valuation` context may be presented side-by-side with their own sessions, but session compatibility authorizes only descriptive comparison. It never authorizes a joint setup-quality/cheapness conclusion, VALUE eligibility, research priority, entry action, recommendation, probability, expected return, or sizing.

If `market_wide_current_valuation` is present, report each Producer method independently with its exact `status`, `applicability`, value, share-authority tier, financial period/basis, blockers/warnings, session, and input/lineage identities. `RESEARCH_USABLE` is research-only, not `READY`, authoritative valuation, or VALUE eligibility; `NOT_APPLICABLE` (including bank/securities industrial EV methods) is neither missing nor blocked. The presence of P/E, P/B, P/S, EV, EV/Sales, or EV/EBITDA does not establish cheapness, VALUE eligibility, target price, intrinsic value, DCF, BUY/SELL, recommendation, or position size. Keep methods from distinct sessions separate and do not manufacture a ticker-wide valuation verdict.

If its optional nested `screening_comparison` extension is present, it is deterministic descriptive evidence from the same retained current-session artifact, not advice. Preserve `coverage_disclosure`, `screen_definitions`, `screen_membership_counts`, every per-screen `member`/`status`/coverage result, source lineage, quality state, and the ticker's market-relative/sector-relative percentile or bucket context exactly. Screen flags are independent dimensions, never ingredients of a composite opportunity score; descriptive percentile or bucket context is not an ordinal market ranking. A `UNAVAILABLE` screen, stale/session-missing technical state, unavailable liquidity state, or sector-relative `UNAVAILABLE` result must be reported as unavailable with its reason, never converted to zero, neutral, or a negative signal. The retained four insufficient sector cohorts remain unavailable. SHB's `g1_v_reconciliation_verdict="OTHER"` warning and its full reconciliation warning remain binding wherever screening liquidity context is cited. Do not infer traded value, turnover, ADV/ADTV, sizing, execution, forecast, probability, target price, valuation, or BUY/SELL/HOLD from this extension; `screening_comparison.is_actionable=false` always.

If `watchlist_tactical_entry_classifier` is present, treat it as a deterministic tactical entry-state classification for human review only, never an execution instruction, order, or automated trade signal (`is_actionable=false` and `requires_human_review=true` always). It reports `market_state` (contemporaneous breadth/regime context shared by every ticker in the same build, never a market forecast or timing call, and never a gate the model may use to override a ticker's own `entry_state`), `ticker_structure_state` (the ticker's own raw trend/momentum posture), `entry_state` (one of nine states: `DOWNTREND`, `SELLING_PRESSURE_EASING`, `EARLY_REVERSAL_CANDIDATE`, `BASE_BUILDING`, `SIDEWAYS_NEUTRAL`, `BREAKOUT_READY`, `UPTREND_CONFIRMED`, `DISTRIBUTION_RISK`, `BREAKDOWN_RISK`), and two separate, deliberately not conflated action fields (2026-08-23 closeout correction). `entry_action` is the PRIMARY field for whether to enter: a fixed lookup from `entry_state` (`EARLY_ENTRY`, `BUY_ON_CONFIRMATION`, `ACCUMULATE_IN_BASE`, `WAIT`, or `AVOID`) that never returns `HOLD_DO_NOT_ADD` or `REDUCE_EXIT`, because those presuppose an existing position this classifier has no holdings input to confirm. `action` is a SECONDARY, position-management-conditional fixed lookup from `entry_state` (`EARLY_ENTRY`, `BUY_ON_CONFIRMATION`, `ACCUMULATE_IN_BASE`, `HOLD_DO_NOT_ADD`, `WAIT`, `AVOID`, or `REDUCE_EXIT`), only meaningful if the reader already holds the ticker -- never use `action` to answer whether to enter a ticker whose holdings are unknown or zero; use `entry_action` for that question instead. It also reports `evidence_for`/`evidence_against` (deterministic strings citing already-computed values, never a basis to extend or contradict with free-form reasoning), `confirmation_trigger`, `invalidation`, `data_quality` (including `confidence` and `warnings`), `horizon` (`NEXT_SESSION_WATCH`, `SHORT_TERM_FEW_SESSIONS`, or `MULTI_WEEK_SWING`), `is_full_position_ready`, and `position_sizing_status`. `EARLY_REVERSAL_CANDIDATE` and `BASE_BUILDING` are early/base language only -- never describe either as a confirmed bottom, a confirmed reversal, or a confirmed uptrend; report them with their own carried `invalidation`, which is deliberately stricter and faster than a confirmed-trend state's. `is_full_position_ready` is unconditionally `false` and `position_sizing_status` is unconditionally `"NOT_EVALUATED"` for every ticker, regardless of `entry_state`/`entry_action`/`action` -- position sizing is not implemented anywhere in this pipeline. `EARLY_ENTRY` and `ACCUMULATE_IN_BASE` never carry `is_full_position_ready=true` under any circumstance, and neither does any other state -- do not describe either action as appropriate for a full-size position, and do not report or imply full-position readiness for any ticker under any condition. `fundamental_context.status = "NOT_IN_FUNDAMENTAL_COHORT"` and an `authority_tier` of `BLOCKED`/`PROVIDER_RESEARCH` are data-coverage limitations that narrow `horizon` and lower `data_quality.confidence`; they never by themselves force a `WAIT` action when the tactical evidence is otherwise sufficient, and never invent a fundamental fact. `blocked_outputs` on this lane and the `state_taxonomy`/`action_taxonomy`/`action_by_entry_state`/`entry_action_taxonomy`/`entry_action_by_entry_state` tables travel with every ticker; never derive an ordinal ranking, opportunity score, probability, target price, or portfolio-sizing figure from any field in this section.

If `current_opportunity_decision_context` is present, it is the sole Producer authority for the all-lane `daily_opportunity_decision_queue/v1` context. Keep `full_priority_now` separate from `legacy_human_review_queue`: the former is the complete all-strategy research-priority membership, while the latter is the existing evidence-gated tactical human-review policy. Never call the legacy cohort “top 47 stocks,” treat it as a fixed cap, or substitute it for the full PRIORITY_NOW output. Preserve `ticker_record.eligible_strategies` and `ticker_record.lane_specific_priority` exactly, including more than one strategy/lane per ticker; do not choose a best strategy or synthesize a global ordering or score. `ticker_record.research_priority_tier` is research priority only and is distinct from `ticker_record.entry_action`, `ticker_record.entry_relevant`, trade readiness, full-position readiness, and sizing authority. In particular, a `PRIORITY_NOW` ticker whose `entry_action` is `AVOID` remains `AVOID`; never rewrite it into a BUY, trade, or entry signal. Report `invalidation_or_context_warnings`, blocking reasons, source identities, `legacy_comparison`, and every `authority_boundary` blocker exactly as supplied. An absent context remains absent; blocked, unavailable, and non-entry-relevant fields are limitations, never neutral/default values or signals. `is_actionable=false` always; no ranking, recommendation, probability, target price, sizing, portfolio, or execution output may be derived from this section.

When synthesizing across multiple analytical lanes (fundamental brief, price analytics, market risk, foreign flow, corporate events), maintain strict categories across **Fact**, **Data Warnings / Limitations**, **Inference**, **Conflicting Evidence**, **Hypotheses**, **Missing Evidence**, and **Invalidation Conditions**. When qualified evidence lanes point in materially different directions (for example, constructive fundamental facts alongside negative bounded-window price returns or drawdowns): (1) state the relevant facts; (2) state their limitations and warnings; (3) identify the **Conflicting Evidence** explicitly before forming any higher-level inference; (4) only then form a bounded inference; (5) preserve missing evidence; and (6) do not resolve the disagreement by inventing confidence or an automatic BUY/SELL or directional rating. Synthesize in logical order: (1) fundamental/business quality, (2) price/technical behavior, (3) benchmark/market risk, (4) foreign flow, (5) corporate/event evidence, (6) warnings/missing evidence.

Structural Synthesis Example: When `current_state_price_analytics` reports a qualified bounded-window return or drawdown alongside an unavailable indicator (e.g. `sma_20.status = unavailable`), and `current_state_market_risk` reports a computable beta and correlation over a bounded `paired_return_count` (`MATHEMATICALLY_COMPUTABLE`), classify the exact recorded metrics as Fact, report `pit_backtest_eligible=false` and `is_actionable=false` under Data Warnings, report unavailable indicators as unavailable without inferring values, describe market risk metrics as bounded by their paired sample size, and state any disagreement with fundamental facts under Conflicting Evidence. Do not issue a recommendation, target price, or claim short-window paired returns prove statistical robustness.

Prohibited claims for these lanes: (1) BUY/SELL/HOLD recommendations or directional ratings from these lanes alone; (2) target prices or valuation claims; (3) claiming RSI or any technical indicator is an independent buy or sell signal; (4) treating unavailable SMA20 as known or inferring price relative to SMA20; (5) claiming a current-state beta is a permanent or true long-term risk score; (6) claiming correlation proves causation; (7) claiming a bounded `paired_return_count` or `MATHEMATICALLY_COMPUTABLE` sample adequacy is statistically robust; (8) treating foreign net buy VALUE as proof of institutional accumulation; (9) treating current-state analytics as PIT/backtest evidence; (10) claiming missing evidence is zero; (11) turning one `current_state_relative_valuation` multiple into a cheap/expensive, undervalued/overvalued, BUY/SELL/HOLD, expected-return, or target-price conclusion; (12) describing a `current_state_relative_valuation` vs. `relative_valuation` difference as a "change" unless `historical_comparison` itself marks that method `status="comparable"`; (13) silently mixing financial figures from two different `financial_period`s into one multiple, or presenting an `unavailable`/`incomparable` valuation method as if it were a qualified zero or a neutral value; (14) computing or implying a traded value, turnover, ADTV, ADV, position size, or execution capacity from `market_wide_current_liquidity_research`'s `grossTradeAmount`-derived fields or any other field in that section; (15) treating a non-`EXACT_MATCH` `g1_v_reconciliation.verdict` as an error, rounding artifact, or something to silently correct rather than an explicit warning to report; (16) treating `INCOMPLETE`/`MISSING`/`PROVIDER_REJECTED` as equivalent to each other, to zero liquidity, or to a ticker outside the retained universe (an absent key); (17) describing `market_wide_current_descriptive_research`'s same-session breadth/sector/technical-feature statistics as covering the full `current_active_equity_denominator` when the reported `observed_session_cohort`/`same_session_technical_feature_available_count` is smaller; (18) reporting a stale (`is_current_session=false`) technical-feature value as if it were the current session's return, momentum, or trend; (19) filling in, estimating, or treating as zero/neutral a sector whose `sector_state.status` is `UNAVAILABLE_INSUFFICIENT_COVERAGE`; (20) deriving a ranking, recommendation, probability, target price, portfolio weight, position size, or traded-value/turnover/ADV/ADTV figure from any `market_wide_current_descriptive_research` field, including its `blocked_outputs` list itself; (21) describing a `watchlist_tactical_entry_classifier` `entry_state` of `EARLY_REVERSAL_CANDIDATE` or `BASE_BUILDING` as a confirmed bottom, a confirmed reversal, or a confirmed uptrend; (22) treating `action="EARLY_ENTRY"` or `action="ACCUMULATE_IN_BASE"` as appropriate for a full-size position, or overriding a `false` `is_full_position_ready`; (23) fabricating a probability of success, a target price, an expected return, or a position-size/share-count figure anywhere in the `watchlist_tactical_entry_classifier` lane; (24) treating `watchlist_tactical_entry_classifier.market_state` as a market forecast or timing call, or as grounds to override a ticker's own `entry_state`; (25) treating a `NOT_IN_FUNDAMENTAL_COHORT` or `BLOCKED` `fundamental_context` as proof a tactical setup is invalid, rather than as a coverage limitation that narrows horizon and confidence; (26) treating `watchlist_tactical_entry_classifier`'s output as an automated trade signal, order, or execution instruction rather than descriptive context requiring human review; (27) treating `action`'s `HOLD_DO_NOT_ADD` or `REDUCE_EXIT` value as an answer to whether to enter a ticker when it is not known whether the user currently holds it -- use `entry_action` for that question instead; (28) claiming or implying `is_full_position_ready=true`, or any other full or complete position-sizing readiness, for any ticker in the `watchlist_tactical_entry_classifier` lane -- `position_sizing_status` is always `NOT_EVALUATED` and position sizing is not implemented anywhere in this pipeline; (29) treating `market_wide_historical_research_context` as historical performance, alpha, probability, or backtest evidence, or translating its `structural_state` into `entry_action` or strategy eligibility; (30) treating a `market_wide_current_valuation` `RESEARCH_USABLE` method as authoritative valuation, or treating any valuation multiple as cheapness, VALUE eligibility, a target price, intrinsic value, DCF, BUY/SELL, recommendation, or position sizing; (31) combining `market_wide_historical_research_context` with `market_wide_current_valuation`, even when sessions are valid, into joint setup quality, cheapness, VALUE eligibility, research priority, entry action, recommendation, probability, expected return, or sizing.


If `qualified_research_brief` is present, treat it as the authoritative compact research input. Render **Qualified Facts**, **Data Warnings / Limitations**, **Analysis / Inferences**, **Bear / Base / Bull**, **Key Risks**, **Catalysts / Conditions**, **Invalidation**, **Historical Research Conclusion**, and **What Cannot Yet Be Concluded** as separate sections. Do not recompute, omit blocked liquidity, convert `not_applicable` bank/corporate fields, or infer portfolio context. Its prohibited_claims list remains binding.

If `qualified_cohort_comparison` is present, treat it as the sole authority for **Qualified Cohort Context**. It is a historical, descriptive cohort comparison—not a peer group, score, or investment ranking. Preserve Producer ratios and states exactly; do not recompute values, calculate FX conversions, compare absolute PVD USD amounts with VND amounts, or add a winner/loser interpretation. Keep `cross_sectional_comparison` separate from `multi_period_trend`; the latter is currently insufficient history. You may state an exact Producer-supported observation such as one ticker's OCF/NI being higher than another's, but never translate it into BUY/HOLD/SELL, target price, cheap/expensive, better investment, expected return, liquidity, position size, or allocation language. Use each row's source fact identities and limitations when explaining a comparison.

If `qualified_research_delta` is present, treat it as the sole authority for **What Changed Since Previous Qualified Snapshot**. State a change only when its `comparison_status` is `comparable` or `partially_comparable` and the Producer status is a change; never independently diff facts, quality, risks, scenarios, invalidations, portfolio gates, or conclusions. If comparison is `blocked`, `incomparable`, `not_comparable`, `unavailable`, or unchanged, report that boundary rather than a thesis change. Preserve the Producer's unchanged critical limitations, including blocked liquidity and portfolio context. A qualitative invalidation with `trigger_evaluation=unavailable` is not triggered. The existing prohibited claims remain binding.

If `qualified_research_change_events` is present, it is the sole authority for concise answers about what changed. Explain only its Producer event family, before/after state, and provenance references; `NO_CHANGE` means no qualified semantic research change. A change event is never bullish, bearish, a BUY/HOLD/SELL, a better/worse investment, valuation, return, or allocation signal.

If `ticker_capability_matrix` is present, treat every lane's Producer status, reason codes, dependencies, and descriptive-only marker as binding. Do not recompute or upgrade a capability: `descriptive_only` market observations are not generic price, valuation, liquidity, sizing, execution, or backtest evidence; `blocked` and `blocked_input` claims must be presented as unavailable boundaries; and `not_applicable` must not be described as missing or unknown. A matrix availability only permits discussion within that lane's stated authority and does not create a recommendation or current-market conclusion.
```

### Expected output

Scope/cutoff, validation gate, factual tables, Corporate Intelligence facts by source when available, data warnings/unknowns, cautious interpretation, missing/conflicts, provenance and limitations.

## 2. Two-ticker comparison template

### Purpose

Compare two packages on compatible fields without forcing a winner.

### Required input

Two context packages, compatible cutoff/period where possible, plus Project Knowledge.

### Prompt

```text
Compare {TICKER_A} and {TICKER_B} using only their attached context packages.

First create a compatibility check for generated_at, latest price date, financial period/type, unit status, missing sections and provenance. Do not compare a field when unit, period or definition is incompatible.

For compatible fields, compare current metadata, price coverage/liquidity/returns, financial coverage and reported values, valuation inputs already present, technical snapshots, shareholder availability and data readiness. Separate facts from inference. Do not rank expected returns, declare a winner or recommend buying/selling. State differences potentially caused by missing data, scale, timing or business-model differences.
```

### Expected output

Compatibility matrix, comparable facts, non-comparable items, balanced trade-offs, gaps and provenance.

## 3. Context-package screening template

### Purpose

Screen only the supplied package set under explicit criteria. This is not a full-market screen or investment ranking.

### Required input

Batch manifest, batch validation report, up to ten context packages, explicit screening type and thresholds.

### Prompt
