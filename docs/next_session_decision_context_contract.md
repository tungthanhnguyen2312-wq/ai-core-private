# Next-Session Decision Context Contract V1

`ai_next_session_decision_context/v1` (`builders/next_session_decision_context.py`) is a read-only Consumer adapter for the Producer's serialized `next_session_decision_brief/v1` artifact and the private-Git handoff package it travels in (`ai_handoff_publication.py`'s own output: `ai_research_session_bundle.json`, `daily_opportunity_decision_queue_artifact.json`, `ai_research_bundle_manifest.json`, the optional `previous_session_bundle_<session>.json`, and `next_session_decision_brief.json`). It imports no Producer Python and recomputes nothing -- every comparative figure, availability state, and label is read verbatim from the brief.

## Loading and fail-closed validation

`load_next_session_decision_package(build_dir, expected_session=..., expected_previous_session=None, expected_producer_checkpoint=None, expected_lineage=None)` accepts only an already-resolved immutable package directory; it never scans a directory tree or selects "the latest" build. It cross-verifies: the brief's own `schema_version`/`contract_version`; `current_session`/`previous_qualified_session` against what the caller expects, including strict chronological ordering; the brief's self-reported `artifact_identity` against its own `artifact_sha256`; the current (and, when a previous session is expected, the previous) session bundle's real file-level sha256 against what the brief's `binding` claims; the manifest's `operation_identity`/`producer_head` against the brief's binding and (opt-in) an expected checkpoint; and, when a package-level lineage record is supplied (e.g. the handoff repo's own `LATEST.json`), every one of its recorded hashes and identities. `load_from_handoff_latest(handoff_repo_root, ...)` reads that repo's fixed `LATEST.json` pointer -- one explicitly named file, not a scan -- and resolves the rest from it. Any mismatch raises `NextSessionDecisionContextError` with a specific reason code; nothing is silently coerced or partially accepted.

## Output shape

`build_context(package)` is a pure transform producing `identity`, `source_lineage`, `authority_boundary`, `market_transition`, `sector_transition`, `opportunity_transition`, `lifecycle_transition`, `recommendation_transition`, `invalidation_transition`, `tactical_transition`, `risk_context`, `next_session_watch_conditions`, `missingness`, and `ai_narrative_contract`. The nine transition/context sections are verbatim deep copies of the brief's own sections (renamed only where the brief's own key differs, e.g. `lifecycle` -> `lifecycle_transition`, `correlation_concentration_context` -> `risk_context`); `missingness` is a mechanical rollup of each section's own `availability`/`reason_codes`, so an `UNAVAILABLE`/`PARTIAL`/`NOT_APPLICABLE` section stays visible rather than silently dropped.

`lifecycle_transition` (scope `SESSION_BUNDLE_COMPARABLE_TICKER_COHORT`, sourced from `multi_session_thesis_recommendation_lifecycle/v1`) and `tactical_transition` (scope `FULL_MARKET_WATCHLIST_TACTICAL_ENTRY_CLASSIFIER`, sourced from `watchlist_tactical_entry_classifier`) are two separately scoped contracts with different cohorts and denominators -- the Consumer verifies each section's own source-identity prefix and fails closed (`*_TRANSITION_UNEXPECTED_SOURCE_IDENTITY`) if it ever drifts, and never merges them into one "technical signal." `recommendation_transition`/`invalidation_transition` preserve `PARTIAL`/`MISSING_PREVIOUS_CONTEXT` exactly; a per-ticker record missing previous context is never translated into `UNCHANGED`, `NEUTRAL`, `WAIT`, or `SELL`. `risk_context` (the C2 correlation/concentration engine) preserves `NOT_APPLICABLE` and its reason codes exactly -- as of the 2026-08-28 governed session, no qualified pair-bound C2 artifact exists yet.

## AI narrative contract

`ai_narrative_contract` is a static, deterministic instruction block (never derived from session data) naming the nine required narrative sections (market state transition; breadth and participation; sector rotation; opportunity-set changes; key tickers to monitor; thesis/recommendation/invalidation changes; risk/concentration limitations; next-session IF/THEN playbook; missing evidence/uncertainty), this repository's existing Fact/Derived/Inference/Opinion-scenario evidence taxonomy (`knowledge/AIUsageRules.md`), label-preservation rules, and forbidden outputs (probabilities, target prices, expected returns, position sizing, allocation weights, unsupported BUY/SELL, unsupported causal explanations, external news/macro claims not present in the supplied context). Outside research, if supplied separately, must be labeled EXTERNAL and can never overwrite Producer evidence. See `prompts/ai_analysis_templates.md` template 5 for the governed downstream prompt.

## Known Limitations

- This contract is market-wide and session-scoped; it does not replace the per-ticker templates and is not mixed with a `{TICKER}_context.json` in the same request.
- `risk_context` is `NOT_APPLICABLE` for every session produced so far -- this contract does not itself change that; it only reports it faithfully.
- `is_actionable=false` always; no ranking, recommendation, probability, target price, or sizing output may be derived from this context.
